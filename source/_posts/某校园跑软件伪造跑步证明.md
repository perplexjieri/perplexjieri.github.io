# 某校园跑软件逆向分析记录

## 一、前期准备

- **设备**：Nexus 5X（root）
- **工具**：Frida、jadx-gui

## 二、背景知识：什么是伪造签名

**伪造签名攻击**：攻击者修改了别人的 APK 后，让 App 内部（或某个验证方）的签名校验逻辑读到"原作者的签名"，从而相信"这个包没有被篡改过"——尽管它实际上已经被改过、而且是用攻击者自己的密钥重新签的名。

攻击是怎么成立的：先理解正常世界——安卓系统安装 APK 时会严格验证签名。你改了包里的任何一个字节，原签名立刻作废，系统会拒绝覆盖安装。攻击者唯一的出路是用自己的密钥重签——这完全合法合规，系统也认，因为系统只管"这个包从头到尾没被第三方改过"，不管签它的人是谁。

## 三、分析过程

### 1. 动态抓包，定位协议

先用 Frida 写一段抓包代码，观察 App 的网络行为。

**Python 驱动：**

```python
import frida, time

PKG = "com.tanma.x"
JS = open(r"C:\Users\27313\Desktop\x\hook_okhttp.js", encoding="utf-8").read()

def on_message(message, data):          # JS 里 send() 的数据都到这
    if message["type"] == "send":
        print(message["payload"], flush=True)

device = frida.get_usb_device(timeout=10)  # 经 adb USB 找到手机上的 frida-server
pid = device.spawn([PKG])                 # 冷启动 App，进程暂停在入口
session = device.attach(pid)              # 附上注入的 agent
script = session.create_script(JS)        # 编译我们的 JS
script.on("message", on_message)          # 注册回传通道
script.load()                             # 注入并执行 → hook 生效
device.resume(pid)                        # 放行，App 继续跑
time.sleep(45)                            # 采集窗口
```

**Hook 脚本（hook_okhttp.js）：**

```javascript
Java.perform(function () {
    // 从 ART 运行时里拿到这个 Java 类的反射句柄
    var Chain = Java.use('okhttp3.internal.http.RealInterceptorChain');

    // 把 proceed 方法"偷梁换柱"：原方法体被替换成这个函数
    Chain.proceed.overload('okhttp3.Request').implementation = function (request) {

        // ---- 进：请求还没发出去，是明文 ----
        log(request.method() + ' ' + request.url().toString());
        var hs = request.headers();
        for (var i = 0; i < hs.size(); i++) log('  ' + hs.name(i) + ': ' + hs.value(i));
        var body = request.body();
        if (body !== null) {
            var buf = Java.use('okio.Buffer').$new();  // 借 OkHttp 自家的 Buffer 读 body
            body.writeTo(buf);
            log('  [body] ' + buf.readUtf8());
        }

        var response = this.proceed(request);  // 调用"原版" proceed，请求真正发出

        // ---- 出：响应刚回来，还是明文 ----
        log('----- [RESPONSE] code=' + response.code() + ' -----');
        log('  [body] ' + response.peekBody(1024 * 1024).string());  // peek=偷偷看但不消费
        return response;
    };
});
```

**主要逻辑**：`spawn`（让 App 停在入口处出生）→ 把 JS 代码注入进去 → `resume` 放行 → App 每调用被 hook 的函数，JS 里的 `send()` 就把数据发回电脑。

**还原后的逻辑（Kotlin 风格伪码）：**

```kotlin
class MyInterceptor : Interceptor {

    companion object {
        private const val APPKEY = "389885588s0648fa"
        private const val APPSECRET = "56E39A1658455588885690425C0FD16055A21676"
        private val UTF8 = Charset.forName("UTF-8")
        private val SPECIAL = listOf(" ", "~", "!", "(", ")", "'")
    }

    override fun intercept(chain: Interceptor.Chain): Response {
        val request = chain.request()
        val signStr = StringBuilder()

        // 1. 查询参数: TreeSet 收集 = 字典序 + 去重，只取每个参数的第一个值，空值跳过
        val names = TreeSet<String>().apply { addAll(request.url().queryParameterNames) }
        for (name in names) {
            val value = request.url().queryParameterValues(name).firstOrNull() ?: continue
            if (value.isNotEmpty()) signStr.append(name).append(value)
        }
        signStr.append(APPKEY).append(APPSECRET)

        // 2. body 原文追加（字符集听 Content-Type 的，默认 UTF-8）
        request.body()?.let { body ->
            val buffer = Buffer()
            body.writeTo(buffer)
            signStr.append(buffer.readString(body.contentType()?.charset(UTF8) ?: UTF8))
        }

        // 3. 特殊字符分支: 剔除后整体 URL 编码，MD5 大写 + "encodeutf8" 后缀
        var dealStr = signStr.toString()
        var spoiled = false
        if (dealStr.isNotEmpty()) {
            for (c in SPECIAL) if (c in dealStr) { dealStr = dealStr.replace(c, ""); spoiled = true }
            if (spoiled) dealStr = URLEncoder.encode(dealStr, "utf-8")
        }
        val mdSign = if (spoiled)
            MD5Digest.encodeByMD5(dealStr)!!.uppercase() + "encodeutf8"
        else
            MD5Digest.encodeByMD5(signStr.toString())!!.uppercase()

        // 4. 加头放行；读不到用户信息就裸请求放行（防御性容错）
        val signed = try {
            val user = PreUtil(Constants.SP_NAME_USER).getValue(Constants.SP_USER, User::class.java, null)
            if (user != null) request.newBuilder()
                .addHeader("token", user.oauthToken?.token.orEmpty())
                .addHeader("appKey", APPKEY)
                .addHeader("sign", mdSign).build()
            else request.newBuilder()
                .addHeader("appKey", APPKEY)
                .addHeader("sign", mdSign).build()
        } catch (ex: Exception) {
            ex.printStackTrace(); request
        }
        return chain.proceed(signed)
    }
}
```

**轨迹序列化 `getTrackToString()`：**

```java
public final String getTrackToString(int effective) {
    List<Track> list;
    if (effective == 1) {
        // 只取"有效"轨迹点（过了精度过滤的）
        list = ContextExtKt.daoSession(this.context).getTrackDao().queryBuilder()
                .where(TrackDao.Properties.Effective.eq(effective)).list();
    } else {
        // effective=0 → 全量原始点（这就是 realityTrackPoints 的来源）
        list = ContextExtKt.daoSession(this.context).getTrackDao().loadAll();
    }
    StringBuilder sb = new StringBuilder("[");
    for (Track track : list) {              // jadx 展开的 forEachIndexed，等价于此
        sb.append("\"");
        sb.append(track.getLongitude()); sb.append('-');  // 注意顺序：经度在前！
        sb.append(track.getLatitude());  sb.append('-');
        sb.append(track.getTime());      sb.append('-');
        sb.append(track.getAccuracy());
        sb.append(list.get(list.size()-1) == track ? "\"" : "\",");
    }
    sb.append("]");
    return String.valueOf(sb);
}
```

public final int getDistance() {
    List<Track> list = daoSession(...).queryBuilder()
            .where(TrackDao.Properties.Effective.eq(1)).list();
    Track track = null;
    float totalDistance = 0.0f;
    for (Track value : list) {

            totalDistance += AMapUtils.calculateLineDistance(latLng,

    }

}

### 4. 伪造工具的对照实现（逻辑还原）

#### ① 签名复刻 —— `SignUtils.get()`（开门的钥匙）

把 `MyInterceptor` 的算法**逐行搬过来**，连同从 APK 里抠出的密钥：

```java
private static final String APPKEY = "389885588s0648fa";      // ← 从 X 提取
private static final String APPSECRET = "56E39A1658455588885690425C0FD16055A21676";

public static String get(Map<String,String> query, String body) {
    StringBuilder sb = new StringBuilder();
    for (String str : new TreeSet(query.keySet())) {   // TreeSet排序，同官方
        sb.append(str).append(query.get(str));
    }
    sb.append(APPKEY).append(APPSECRET);
    if (body != null) sb.append(body);
    // ...下面六连 contains/replaceAll（空格 ~ ! ( ) '）+ URLEncode
    //      + "encodeutf8" 后缀——和 MyInterceptor 一字不差
}
```

有个手抄痕迹很有意思：它的请求头用的是小写 `appkey`（官方是 `appKey`），HTTP 头不区分大小写所以能过——典型的手工移植特征。

## 五、防御建议（如何防止此类伪造现象）

### 1. 服务端数据校验（最重要）

伪造工具能完美复刻协议，却复刻不了真实 GPS 数据的物理统计特征，所以防线必须建在服务端：

| 校验项 | 原理 | 成本 |
|---|---|---|
| 瞬时速度连续性 | 伪造轨迹相邻点速度恒为整数（1/2/3/4 m/s），真实速度是连续值 | 极低 |
| 轨迹时长 = runTime 字段 | 伪造工具的时间戳按随机速度累加，与手填时长脱钩 | 极低 |
| 三点共线性检测 | 伪造插值点严格落在直线上，真实 GPS 有横向抖动 | 低 |
| accuracy 分布检验 | 伪造精度服从均匀分布 U[0,10)，真实 GPS 右偏分布 | 低 |
| 速度自相关 | 人类速度序列平滑（lag-1 自相关≈0.9），伪造序列≈0 | 中 |
| 里程-轨迹强绑定 | runDistance 必须等于轨迹逐段累计（含系统补偿系数容差） | 低 |
| 跨账号轨迹聚类 | 伪造模板复用导致不同账号轨迹精确命中相同坐标 | 中 |

### 2. 字段完整性强制

伪造工具提交的 `vocalStatus`、`innerSchool`、`distanceTimeStatus` 恒为 null，`realityTrackPoints` 是塞的垃圾串。服务端应校验：

- 必填字段非空且取值合法
- `realityTrackPoints` 必须可解析为合法轨迹数组
- `realityTrackPoints` 与 `trackPoints` 的点数比值合理（原始点 ≥ 有效点）

### 3. 协议层加固

- **签名升级**：MD5 无时间戳、无 nonce，可离线复刻。应改为 HMAC + 时间戳 + 随机数防重放
- **密钥保护**：appKey/appSecret 硬编码在 Java 层等于公开。至少下沉到 native 层并做动态派生，理想方案是服务端下发会话密钥
- **一次性提交令牌**：`startRun` 时服务端下发提交令牌，`saveRunRecord` 时校验令牌与开始时间、会话的一致性，防止"登录即提交"的极简会话

### 4. 行为与抽查机制

- **请求序列分析**：真实客户端有持续轮询、地图加载等并发行为；协议复刻工具的会话只有"登录→查询→提交"极简序列，特征明显
- **声纹抽查强制化**：跑步中随机声纹验证，未通过抽查的记录标记待复核
- **人工抽查轨迹回放**：定期在地图上回放轨迹形态，肉眼即可识别"完美直线段"这类异常
- **设备指纹一致性**：提交时的设备信息与该账号历史设备比对，突变即标记

### 5. 架构原则

**客户端控制不构成安全边界**。无论签名、加壳还是混淆，客户端提交的一切自证字段都可被复刻；真正的安全只能来自服务端对数据物理合理性的检验。这是本案例分析得出的核心结论：攻击者跨越了协议层的所有门槛，最终暴露在数据层的统计学规律之下。
